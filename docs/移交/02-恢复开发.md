### ⚠️ 环境漂移（2026-09 盘点发现，接手必看）
本机 `python` 实际解析到 **LibreOffice 自带的 Python 3.13.15**，且 **numpy、websockets 都没装**：

```
$ python -V
Python 3.13.15
$ python -c "import numpy"
ModuleNotFoundError: No module named 'numpy'
```

影响的脚本：
- `update-server/release.py`、`update-server/delta.py`（差分编码用 numpy 加速）→ 需要 **numpy**
- `update-server/pk_server.py`、`tools/pk_server_smoke.py`、`tools/pk_guest.py` → 需要 **websockets**
- `tools/snake_autoeat.py` / `snake_speed_check.py` / `klotski_anim_check.py` / `gomoku_undo_check.py`（像素识别）→ 需要 **numpy**、**Pillow**、**scipy**

两种修法（任选）：
1. **给当前 Python 装依赖**：`python -m pip install numpy websockets pillow scipy`（本机 pip 需用 `python -m pip`，`pip` 不在 PATH）
2. **指定专用 Python**：另装一个干净的 3.11/3.12，命令里显式用它的路径，例如 `"C:/Python312/python.exe" update-server/release.py`

> 提醒：`release.py` 与 `pk_server.py` 是发布/线上链路的关键脚本，动手前先跑一次
> `python -c "import numpy"` 确认依赖在，别在发版中途才发现缺包。

## 二、日常开发

```bash
# 构建
./gradlew assembleDebug
# 装到模拟器（先启动 AVD BrainQuest）
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.brainquest.game/.MainActivity
# 截图
adb exec-out screencap -p > screen.png
```

### ⚠️ 关于"debug APK 却是正式签名"
`app/build.gradle.kts` 里 debug 与 release **都**在 `keystore.properties` 存在时使用正式签名配置，
且两者都开了 R8 混淆与资源压缩。所以：
- 有 `keystore.properties` → `assembleDebug` 产出的包**可以直接给线上老用户原地更新**（这正是发版流程用 debug 包的原因）；
- clone 下来没有 `keystore/` → 包自动退回 Android 默认 debug 签名，**装到已装过正式包的机器上会签名冲突**，
  必须先卸载重装（本地数据会丢），或者先把 keystore 恢复回来。

实测证据（同一份代码，两种环境各构建一次，`apksigner verify --print-certs`）：

| 构建环境 | 签名者 DN |
|---|---|
| 工作区（有 `keystore/`） | `CN=BrainQuest, OU=Game, O=ING-49, C=CN` ← 线上正式签名 |
| fresh clone（无 `keystore/`） | `C=US, O=Android, CN=Android Debug` ← 系统默认 debug 签名 |

> 顺带验证了一条重要结论：**fresh clone + `./gradlew clean assembleDebug` 能直接编译成功**
> （2026-09 交接时实测，2m21s，41 个任务）。也就是说这份交接包里的代码是自洽的，
> 缺的只有签名密钥与发布产物，而它们已在 `01-资产与凭据.md` 里列明必须单独备份。

## 四、发版（三步，必须按顺序）

```bash
# 1) 改版本号 + clean 构建 + 拷贝进 apks/
#    app/build.gradle.kts: versionCode +1、versionName 升级
./gradlew clean assembleDebug            # ⚠️ 必须 clean：zipflinger 增量打包会把已删条目留成死空间，APK 虚高
cp app/build/outputs/apk/debug/app-debug.apk update-server/apks/BrainQuest-v<版本>.apk

# 2) 生成内容包 + 差分补丁 + manifest + 自校验
cd update-server && python release.py     # 末尾必须出现 [verify] ✓，不出现禁止发布
#    只发内容包时：python release.py --packs-only

# 3) 发布到 GitHub Releases
cd .. && GH_EXE=E:/Tools/gh-cli/bin/gh.exe python tools/publish_github.py
#    末尾必须出现 ✓ GitHub 托管生效：latest → v<版本>(code N)
```

发版后建议做一次真实链路验证（模拟器可做）：把上一版 APK 用 `adb install -r -d` 装回旧版，
在 App 内「我的 → 设置与更新 → 检查更新」走一遍检查更新 → 内容热更 → 增量更新 → 系统安装 →
确认 `adb shell dumpsys package com.brainquest.game | grep versionName` 变成新版本。
（模拟器访问 GitHub 不通时：`python tools/dev_relay.py`，App 内把更新地址填 `http://10.0.2.2:8000`。）

完整检查单见 `docs/PLAYBOOK.md` §五。**联机是强制同版本**：发了新版，旧版用户之间仍能对战，
但新旧版本之间无法匹配（握手校验 versionName）——这是既定策略。

## 五、联机服务器

```bash
# 部署 / 更新服务器代码（改完 update-server/pk_server.py 后）
PK_SSH_PASS='<口令>' python tools/deploy_pk_server.py
# 线上自检
python tools/pk_server_smoke.py ws://8.148.192.129:8765
# 机器人对手（联机联调用；--quick 需与 App 版本一致才会被配对）
python tools/pk_guest.py --quick 6 1.6.6
```
服务器细节（日志、数据文件、迁移步骤）见 `01-资产与凭据.md` 第三节。服务全名 **`pk-server.service`**（`systemctl status pk-server` / `journalctl -u pk-server -n 100`）。
**改服务器代码后必须 `systemctl restart pk-server`**——`enable --now` 不会重启已运行的服务，
这个坑线上踩过一次（表现为新功能不生效）。

## 六、CI 现状（写了但从未验证）

`.github/workflows/release.yml`：打 `v*` tag 触发 → 校验 tag 与 `versionName` 一致 →
从历史 Release 拉回所有 APK（保证补丁链连续）→ 构建 → 若配置了 Keystore Secrets 则用正式签名
→ `python release.py` → `publish_github.py`。

- **至今没有实战跑过**：仓库里只有 tag `v1.1.1`（早于该工作流），v1.2.0 之后的每一次发版都是本地
  `publish_github.py` 出的。
- **首次启用前务必先配好 4 个 Keystore Secrets**：没配的话 CI 会产出 debug 签名的包，
  发出去会污染签名链，老用户更新直接失败。
- 若要验证它：改版本号 → `git tag v<版本> && git push origin v<版本>` → 看 Actions 日志与
  Release 产物是否与本地发版一致（这条已在 `03-待办与路线图.md` 里列为待办）。
