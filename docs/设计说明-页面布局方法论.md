# 页面设计方法论 —— 每页为什么这样排

> 本文档回答"这页为什么长这样"。任何 UI 改动**先对表再动手**：改布局前先更新对应设计卡，说明依据哪条原则。
> 表层好看（配色/间距/动效）由批31/32 的组件层承担；本文档管的是**布局合法性**——信息放哪、为什么放哪。

## 一、方法论框架：五问

设计或改动任何页面，先回答：

1. **使命**：用户来这页做什么？（一句话，说不出使命的页面就是堆料）
2. **信息优先级**：P0 = 不看就亏 / P1 = 需要时能找到 / P2 = 支持性内容
3. **视觉动线**：第一落点 → 第二 → …（最大最亮的元素必须是 P0）
4. **行动层级**：唯一主 CTA → 次级入口 → 弱化入口（等权按钮 = 没有按钮）
5. **留人钩子**：这页埋了什么"回来/继续"的机制

## 二、心理机制词汇表（留人钩子用这套说话）

| 机制 | 在本项目里的落点 |
|---|---|
| 齐加尼克未完成感 | 「继续冒险·第N关」CTA、关卡列表「▶ 进行中」徽章 |
| 目标梯度效应 | 科目卡 x/8 进度条、关卡列表头部进度、XP 条（越接近完成越有动力） |
| 每日循环 | 签到 + 每日挑战并排卡置顶、每日任务卡片 |
| 损失厌恶 | 🔥 连续挑战 N 天（streak 可见即怕断） |
| 进度可见性 | XP 条、图鉴 x/11、成就 x/y |
| 新鲜感 | 「新玩法」角标（地牢） |
| 强反馈时刻 | 领金币按钮金亮 + "+N" 浮字、答题对错即时变色 |
| 心流（难度匹配） | 关卡难度梯度文案「难度 N」、BOSS 关明示 |

## 三、每页设计卡

### 1. 主页大厅
- **使命**：30 秒内决定"今天玩什么"，顺手带走每日收益
- **P0**：每日签到/挑战（收益入口）｜游戏中心双主角卡
- **P1**：每日任务、联机对战
- **P2**：功能三芯片（错题/商店/成就）、道具、最佳成绩
- **动线**：用户卡（身份锚点+Lv/XP）→ 日常行（收益）→ 任务明细 → 游戏中心（内容选择）→ 联机横条 → 支持系统
- **CTA**：每日挑战卡（金亮+呼吸=可领取）> 游戏主角卡 > 其余全部弱化
- **留人**：每日循环三件套置顶 + 🔥streak + 主角卡层级化（核心玩法/新玩法角标）
- **现状**：✓（批25 布局 / 29 层级 / 31 语义色 / 32 动效均已对表）

### 2. 闯关地图
- **使命**：选今天打哪科（老玩家 3 秒内进战斗）
- **P0**：继续冒险 CTA（直达上次进度关）
- **P1**：已解锁科目卡（进度条+开始胶囊）
- **P2**：未解锁科目（锁+「前一科通过 2 关解锁」= 下一目标预告）
- **动线**：CTA 第一落点（全页唯一暖色金色播放钮）→ 科目网格自上而下即解锁顺序
- **留人**：未完成感（继续）+ 目标梯度（进度条）+ 解锁预告
- **现状**：✓（批30/31）

### 3. 关卡列表
- **使命**：明确"打哪一关"
- **P0**：下一关（主色描边 + ▶ 进行中徽章）
- **P1**：已通关关卡（星星数）、BOSS 关
- **P2**：未解锁（灰化）
- **动线**：头部进度条 → 当前关（列表第一屏）→ 往下扫
- **留人**：目标梯度 x/8 + 当前位置标记（永远知道下一步）
- **现状**：✓（批31）

### 4. 答题战斗
- **使命**：答题→攻击的实时决策
- **P0**：题面+选项 ｜ 双方血条（局面信息）
- **P1**：限时提示、伤害飘字（即时反馈）
- **P2**：提示/跳过（兜底道具，弱化不抢注意力）
- **动线**：敌人（目标）→ 我方（状态）→ 题卡（行动）→ 工具（兜底）
- **留人**：即时反馈（飘字/音效/选项变色）
- **违例 ✗（批33修）**：我方状态条右侧显示金币——金币与战斗决策无关，属于页面噪声，撤出

### 5. 每日挑战（启动页）
- **使命**：讲清规则，促成「开始」
- **P0**：开始按钮（**主 CTA 必须有按钮形态**，不能藏进信息卡）
- **P1**：模式说明、奖励预告（动机钩子）、streak
- **P2**：难度切换指引
- **违例 ✗（批33修）**：整卡可点但视觉是信息卡（用户不确定点哪）；无奖励预告；streak 弱化埋在副标题

### 6. 战斗结算
- **使命**：宣告结果 + 发放收益 + 引导再来
- **P0**：星级结果；P1：奖励；P2：返回
- **现状**：AlertDialog 简单实现（合规但可后续加「再来一局」缩短重开路径）

### 7. 我的
- **使命**：查看积累，进入支持系统
- **P0**：身份卡（头像/Lv/金币）；P1：四统计（语义色）、本周学习、成就/错题/商店入口；P2：设置
- **动线**：身份 → 数字 → 周回顾 → 入口列表
- **留人**：本周学习即空状态也有引导文案（"去闯一闯吧"）
- **现状**：✓（批31/32）

### 8. 商店
- **使命**：花金币（游戏内经济的出口）
- **P0**：金币余额（动态计数动画已有）
- **排序**：道具（效用）→ 主题 → 头像（表达）＝ 效用 > 表达 ✓

### 9. 错题本
- **使命**：学习闭环（错 → 复习 → 掌握）——**教育循环与游戏循环并列**，这是产品定位
- **P0**：今日待复习（艾宾浩斯队列）；P1：全部列表+已掌握标记；P2：导出 CSV
- **现状**：✓

### 10. 设置
- **使命**：个性化 + 维护
- **P0**：音效/震动/考研模式（用户可感）；P1：云存档、更新中心；P2：隐私
- **开发者更新地址 = 长按头部唤出**的隐藏手势，不占普通用户信息层级 ✓

### 11. 联机对战
- **使命**：与真人对局（社交竞争）
- **现状**：独立页（冒烟脚本 39 项锁定语义），入口在主页横条（弱于单人玩法、强于功能芯片 ✓）

### 12. 地牢大厅（横屏）
- **范式**：主机游戏大厅三栏——左职业直选（决策输入）｜中立绘大舞台（情感锚点/聚焦）｜右模式卡+右下大开始键（唯一主 CTA，主机游戏惯例位）
- **留人**：战绩 footer（通关/最高层/击杀 = 进度可见性）、四模式描述文案
- **现状**：✓（批27/28）

### 13. 横屏游戏内 HUD
- **范式**（批24 确立，GameUi.kt 头注）：左上玩家信息 / 顶部目标信息 / 右上功能 / 右下操作簇（右手拇指区 = 主操作）
- **红线**：HUD 元素画在世界变换之外（坑35）；弹窗叠加顺序（坑40）
- **纵深语言**（批34 起）：① 物理纵深=脚下影子（已有）+ Y-sort 遮挡（批36 已做：玩家与敌人按脚底 y 统一排序绘制，谁靠下谁在前）；② 光影纵深=玩家火把光（以玩家为中心的径向暗角，远暗近亮，批34）+ 房间四边内阴影（房间=下沉的坑，批34 补全）+ 玩家微光环（已有）；③ 运动纵深=punch-zoom/震屏/Boss 拉远（已有）。页面级纵深=P0 卡片投影浮起、P2 卡片平贴（批34 主页/地图已应用）；批35 铺满全界面：GamePanel 面板统一柔影（面板=前景浮层）、暗色大厅选中卡浮起（选中=抬高）、GameActionButton 主按钮投影、关卡列表下一关卡 M3 elevation 8dp、每日挑战启动卡 4dp

### 14. 迷你幸存者 / 华容道 / 五子棋 / 贪吃蛇
- 各自交互语义由取证脚本锁定：`klotski_anim_check`（跟手/落格）、`gomoku_undo_check`（悔棋=回到我落子前）、`snake_speed_check`（速度档/返回确认）
- 迷你幸存者弹窗：规则三行 + 最高纪录（目标锚点）+ 主按钮（批33 已修对比度）

## 四、改表流程（硬规则）

1. 改任何页面布局前，先更新本文档对应设计卡（写明依据）
2. 新增元素必须声明属于 P0/P1/P2 哪层，插在哪条动线位置
3. 新增页面必须先写设计卡再写代码
4. 与设计卡冲突的改动 = 违例，要么改设计要么改实现，不许含糊
